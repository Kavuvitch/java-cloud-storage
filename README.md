# Блок 2, часть 1. Вариант 17: облачное хранилище

Готовый учебный проект для Java 17+. Сторонние библиотеки не требуются.

## Запуск в IntelliJ IDEA

1. Распакуйте архив и откройте папку `cloud-storage-17` через File → Open.
2. В File → Project Structure выберите Project SDK 17 или выше.
3. Если требуется, нажмите правой кнопкой по `src` → Mark Directory as → Sources Root.
4. Откройте `src/CloudManager.java` и запустите метод `main` зеленой кнопкой слева.

## Запуск в терминале с установленным JDK 17+

Из папки проекта:

```sh
javac -encoding UTF-8 --release 17 -d out src/BackupOption.java src/CloudStorage.java src/CloudManager.java
java -cp out CloudManager
```

В архиве также есть уже скомпилированные `.class` в `out`. Для них достаточно второй команды.

## Назначение классов

- `BackupOption`: название и стоимость услуги; проверка стоимости в сеттере.
- `CloudStorage`: название, базовая стоимость, тариф, подключенная опция и частота копирования. Конструкторы связаны через `this(...)`.
- `CloudManager`: точка входа, регистрация оплат и статическая статистика.

Все поля закрыты (`private`); для всех полей предусмотрены геттеры, для неизменяемых полей установлен `final`. Тариф выбирается через switch expression.

## Формулы и допущения

Тарифы строго из варианта 17:

| Объем | Надбавка | Множитель |
| --- | --- | --- |
| 100 ГБ | 0% | 1 |
| 512 ГБ | 100% | 2 |
| 2 ТБ | 300% | 4 |

Стоимость без опции = базовая цена × множитель тарифа.

В методичке указана частота резервного копирования в день, но не определены расчетный период и формула доплаты. Поэтому для демонстрации принят расчет за один день: стоимость с копированием = базовая цена × множитель + цена опции × частота. Цена опции трактуется как цена одного копирования; частота — целое число больше нуля. Верхний предел частоты не задан, искусственно не ограничивается.

Без явной частоты выполняется одно копирование в день. При отрицательной/бесконечной цене, NaN, неизвестном тарифе, пустом названии, null вместо опции или неположительной частоте выбрасывается исключение.

Общие условия требуют три перегрузки `calculateFinalPrice`, а таблица варианта называет методы `enableBackup`. Для соблюдения обоих требований реализованы:

```java
calculateFinalPrice()
calculateFinalPrice(BackupOption option)
calculateFinalPrice(BackupOption option, int frequency)
enableBackup(BackupOption option)
enableBackup(BackupOption option, int frequency)
```

Методы `enableBackup` делегируют расчет перегрузкам `calculateFinalPrice`, без дублирования формул. Расчет без аргументов возвращает цену тарифа без опции, как прямо требует общее ТЗ; он не отключает ранее подключенную опцию. Перегрузки с опцией сохраняют ее и частоту в объекте. У опции есть собственная цена, меняемая через сеттер; последующие расчеты используют ее текущее значение.

Статистика меняется только при `registerPayment`, а не при предварительном расчете или подключении услуги. Один вызов означает одну отдельную оплату. Автоматической защиты от повторной оплаты одного объекта нет: повторный вызов трактуется как новая операция.

Для промежуточных денежных вычислений используется BigDecimal, округление HALF_UP до двух знаков; поля цены и выручки имеют тип double. При очень больших суммах double не гарантирует точность копеек, поэтому это учебный пример, а не платежная система.

## Проверенный результат

При базовой цене 100 рублей и цене копирования 10 рублей:

- 100 ГБ без опции: 100 × 1 = 100 рублей;
- 512 ГБ, одно копирование: 100 × 2 + 10 = 210 рублей;
- 2 ТБ, три копирования: 100 × 4 + 10 × 3 = 430 рублей;
- итого: 3 оплаченных заказа, выручка 740 рублей.

Фактический вывод программы сохранен в `console-output.txt`. Проверены компиляция под Java 17, запуск, три тарифа, перегрузки, цепочка конструкторов, связь с опцией, округление, ошибки входных данных и отсутствие изменения статистики от простого расчета.
